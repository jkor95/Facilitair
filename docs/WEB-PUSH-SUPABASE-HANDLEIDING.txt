Wat nog nodig is voor echte pushmeldingen:
1. In het juiste Supabase-project de ACTUELE code van de actieve
   Edge Function 'smart-function' vaststellen.
2. In de database een afzonderlijke tabel voor PushSubscription-endpoints
   maken, gekoppeld aan geauthenticeerde medewerker en apparaat.
   Inschrijven/uitschrijven uitsluitend na server-side authenticatie.
   Endpoint en sleutels niet publiek uitlekken; passende RLS.
3. Server-side VAPID-sleutels genereren; PRIVATE KEY uitsluitend als
   Supabase Secret opslaan. Nooit in GitHub of de browser.
4. Backendacties voor aanmelden, afmelden en VAPID public key toevoegen.
5. Bij een nieuwe melding of nieuwe toewijzing push versturen naar
   medewerkers die meldingen hebben ingeschakeld, rekening houdend met
   urgentie-, rol- en toewijzingsinstellingen.
6. Push per device registreren via PushManager.subscribe in de frontend.
   Op iOS eerst webapp op beginscherm installeren. Afmelden moet de
   abonnementen ook server-side verwijderen.
7. Dubbele notificaties voorkomen (deduplicatie op ticket/event/device),
   ongeldige endpoints opruimen, geen persoonlijke ticketinhoud meesturen.
8. Veilig testen met fictieve tickets en testaccounts voordat frontend
   en backend tegelijk geactiveerd worden.
